# Study Bot — учебный ассистент в Telegram

Telegram-бот на **aiogram 3.x**, который:

- авторизует ученика в Google Classroom (OAuth2),
- показывает актуальные (несданные) домашние задания,
- скачивает вложения задания,
- решает задание через **Google Gemini** (`gemini-1.5-flash`, текст + картинки),
- при необходимости ищет контекст в PDF-учебниках из `data/books/`,
- рисует красивый "тетрадный лист" с ответом через Pillow.

## ⚠️ Важно про безопасность

**Никогда не храните реальные токены/ключи в коде или в чате.** Если вы уже
присылали свой `TELEGRAM_BOT_TOKEN` или `GEMINI_API_KEY` куда-либо в открытом
виде (в переписке, в публичном репозитории и т.п.) — считайте их
скомпрометированными:

- Telegram-токен: зайдите к **@BotFather** → `/mybots` → выберите бота →
  `API Token` → `Revoke current token`, получите новый.
- Gemini API-ключ: перевыпустите его в [Google AI Studio](https://aistudio.google.com/app/apikey).

Новые ключи кладите **только** в файл `.env` (см. `.env.example`), который
никогда не должен попадать в git — он уже добавлен в `.gitignore`.

## Установка

```bash
python -m venv venv
source venv/bin/activate   # Windows: venv\Scripts\activate
pip install -r requirements.txt
```

1. Скопируйте `.env.example` в `.env` и впишите свои ключи:
   ```
   TELEGRAM_BOT_TOKEN=...
   GEMINI_API_KEY=...
   ```
2. Создайте OAuth-клиент в [Google Cloud Console](https://console.cloud.google.com/apis/credentials)
   типа **Desktop App**, скачайте JSON и положите его в корень проекта как
   `credentials.json`.
   - Включите API: **Google Classroom API** и **Google Drive API**.
   - Добавьте себя (и других учеников) в тестовые пользователи OAuth
     consent screen, пока приложение не прошло верификацию Google.
3. (Опционально) Положите PDF-учебники в `data/books/`.
4. (Опционально) Положите рукописный TTF-шрифт в `data/fonts/handwriting.ttf`
   — иначе будет использован обычный аккуратный шрифт.

## Запуск

```bash
python main.py
```

## Как проходит авторизация Google (важно)

Так как это серверный бот с несколькими пользователями, классический
`flow.run_local_server()` не подходит (он открывает браузер локально на
машине, где запущен бот, а не у ученика). Вместо этого используется
стандартный ручной OAuth-флоу для Desktop-приложений:

1. Бот присылает ссылку авторизации Google.
2. Ученик переходит по ссылке, разрешает доступ.
3. Google пытается открыть `http://localhost/?code=...` — страница не
   загрузится (это нормально, никто не слушает localhost), но **код виден
   в адресной строке браузера**.
4. Ученик копирует эту ссылку (или сам код) и присылает её боту в чат.
5. Бот обменивает код на токен и сохраняет его в `tokens/{user_id}.json`.


## Известные упрощения (что стоит доработать под продакшн)

- Поиск контекста по учебникам — лексический (по ключевым словам), а не
  векторный. Для больших библиотек книг стоит перейти на эмбеддинги
  (например, `text-embedding-004` от Google) и векторную БД.
- PDF-вложения задания сейчас не конвертируются постранично в картинки —
  в Gemini уходит только текстовое описание задания. Для сложных PDF со
  схемами/формулами стоит добавить рендер PDF-страниц в PNG (`pypdfium2`
  или `pdf2image`) и передавать их как изображения.
- Хранение токенов в `tokens/*.json` подходит для одного сервера; для
  масштабирования стоит переехать на БД (Postgres/Redis) с шифрованием.
